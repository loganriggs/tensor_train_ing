## Fixed: two robustness gaps in the new `scripts/scaling_grid.py` (before its first GPU job)
1. **Silent short parents.** `train_run` stops at its runtime cap with `stop_reason: runtime_cap` and still writes a `final/` with fewer tokens.
   The driver treated any `final/` as done, so it would have branched every budget from a short parent. Now each stage's endpoint is read from
   `result.json` (`progress.tokens`). A cooldown must end exactly at its budget, or the job fails loudly.
2. **No crash/cap recovery for multi-day parents** (s304m ≈ 95 h). The parent now continues from its furthest resumable checkpoint (a short
   `final/` or the hourly `recovery-*` state; `keep_recovery_checkpoints: 1`) into `parent_c<k>`, as `train_run` requires a new run dir per resume.
   Milestones are looked up across all parent dirs. "Reached" (a pruned `final/` still counts via result.json) is kept separate from "resumable"
   (needs state.pt). The first version conflated them and broke idempotent re-runs; the existing end-to-end test caught it.
