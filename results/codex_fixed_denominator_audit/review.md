Additional fixed-denominator findings, independent of scaling and document aggregation

1. Empty evaluation targets silently produce nonfinite quantitative results (analysis.py:354-365). With one ordinary calibration probe and one evaluation probe whose targets are all -100, fixed_denominator returns NaN for all five metrics: live/fixed CE, KL, absolute logit error and top1 agreement. Calibration inputs are valid and the model is finite; there is simply no scored evaluation target. analyze later replaces NaN text with null, obscuring the reason. Packed windows can legitimately contain no prediction pairs (single-token documents, padding or context-transition masking). Request explicit nonempty calibration-input and evaluation-target counts before statistics, a clear rejected/skipped reason, and finite metric validation. Report both counts and disjointness scope. This avoids passing an unmeasured equivalence test through as a completed quantitative diagnostic.

2. The no-DynamicNorm skip incorrectly asserts class P (analysis.py:333). A softmax-attention model with lagged input/final norms has no DynamicNorm instances, yet operator_audit correctly reports class G. fixed_denominator reports 'no dynamic normalizers (class P at this checkpoint): fixed and live are identical'. Identity of this specific unchanged intervention is true, but the polynomial-class conclusion is false: softmax row normalization remains live. A scalar two-logit softmax example has third derivative 0.060796138691618054 at 0.7 (this alone rules out only quadratic behavior). More generally its bounded, nonconstant restriction to the real line cannot be any finite-degree real polynomial, since every nonconstant real polynomial is unbounded on that line. Request a scope-specific skip: no targeted RMS/GroupRMS denominators; softmax normalization remains dynamic, and operator class comes from the model audit. Do not use absence of DynamicNorm as a polynomiality certificate.

Probe reproduction and exact source hash are in reproduce.py/evidence.json. CPU synthetic tensors only; no GPU, training or corpus reads. Half-batch provenance and cross-split document overlap are being reviewed separately by root.

3. A split by batch index does not establish held-out source tokens. Root reproduction `split_reproduce.py` uses an ordinary PackedSampler with one synthetic validation document and two batches. The first and second batches come from epochs 0 and 1 but have identical hashes, inputs and targets. The diagnostic still labels this as first-half calibration, not in-sample. Current wording states the mechanical split accurately, but it is insufficient evidence for a held-out fixed-denominator approximation. Request document/source-offset split provenance and explicit repeated-target counts, with a disjoint fit/evaluation option or an in-sample label when they overlap. Different documents are stronger separation than different batches; no claim of universal independence follows even from exact-document separation. This is separate from train–validation content leakage, which the wrapper already audits.
